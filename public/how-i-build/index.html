03

Tokens first, then the audit

The lesson that changed my process most. In Tracing Origins I fixed accessibility first and tokenized afterwards. Three days later, in Volcano Explorer, I flipped the order. Deep Lineages started from tokens and a lab to test them, and the contrast fixes took a fraction of the work.

04

Context, not prompts

I talk to Claude like a coworker. The precision lives in two places: a CLAUDE.md in each repo, its memory, and skills, routines that travel between projects.

Three skills distilled from the audits

visual-consistency-qa

Aligns radius, color roles, spacing and type, so they can become tokens.

design-tokens-system

Fixes contrast and sizes in one place, and holds each project's visual identity.

wcag-audit-learning

"Learning" because I check every case by hand and talk each fix through.

05

Run the audit myself

I run the tests and talk each fix through before it's applied, so I understand it instead of just collecting it. Deep Lineages' colors, checked live: contrast, and how they read with color blindness.

06

What I haven't figured out yet

Open branches. If you've solved any of these, I'd like to hear how.

  • Memory that grows. A CLAUDE.md reached 44,000 words and contradicts itself.
  • "It's fixed." I still verify every fix in the browser before I believe it.
  • Real users. It passes my audit, and the apps get a little traffic (I can see it in Vercel Analytics). What I can't see is whether anyone using a screen reader has tried them, or how it went.
  • A team. How does this loop work with engineers and a shared codebase?
